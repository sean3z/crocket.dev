C++ right now

C++ didn't go away while everyone talked about Python. In the TIOBE index for November 2026, C++ is 4th, with a rating of 8.35%. A year earlier it was 3rd, and the rating is down 0.60 points. TIOBE says those ratings come from skilled engineers, courses, and vendors, counted across search engines. The same page says the index isn't about the best language or the one with the most lines of code.

GitHub's 2025 Octoverse measures something else. Nearly 80% of new repositories used just six languages, and C++ is one of the six. The table counts 1,701,552 C++ repositories from September 2024 through August 2025. The growth column on that row is 11.82%, January through August 2025 against the same months in 2024. GitHub's note is performance-critical workloads in game engines, inference, and embedded systems supporting AI. In the AI-tagged slice of the same post, C++ crossed 7,800 repositories, up 11%.

Those two sources don't say the same thing, and they shouldn't be mashed into one "C++ is surging" line. Search interest slipped a place. New public repositories in that language still grew, and GitHub ties the work to inference and other tight loops. Assistants make the typing cheaper. They don't make a tangled service easier to page someone about.

Why the shape helps

crocket is easy to read twice: once for the model, and once for the person who has to triage what the model wrote. A route is one annotated function. A struct is the schema. There's no macro that hides the path, no route table you have to remember to update, and no container that injects dependencies you can't grep. Logging, metrics, auth, and OpenAPI are on because a line in the builder says so. The compiler checks that the capture name matches the parameter.

On call, that small surface is the point. You search for http::post and you have the write path. You search for attach and you have the production behavior. A bad path segment fails the build, with both names in the error, instead of failing as a 404 after the deploy. The JSON decoder and the handler share one struct, so qty can't be a string in the handler and a number in the spec.

Response

Use crocket. Each route is a function, the struct is the body, and the production pieces are attached in one chain instead of discovered at startup. Here's the create and the authenticated read, short enough to review on one screen. /healthz is already registered.

That listing is checks/snippets/orders.cpp, compiled against commit 9b446f8, the same pin as this site. main calls make_app().launch(). The includes are crocket.hpp and auth.hpp.

Reading what it wrote

  1. json::min(1) on qty, and json::min_len / json::max_len on sku, are the validation. A body that fails them never enters create.
  2. auth::require("orders") is the JWT check on the read. who is the principal. This handler doesn't use who.subject yet, so the name is marked unused. The write isn't locked. Copy that annotation onto create when you want it locked too.
  3. .attach(Logger{}) is the request log. .attach(Metrics{}) is GET /metrics. .attach(OpenApi{...}) is GET /openapi.json. .docs is unset on purpose: the Swagger page loads a script from a CDN, and a strict content security policy won't allow it.
  4. .manage(auth::Jwt::oidc(...)) is the verifier. login.example.com is a placeholder issuer, not a server we run.
  5. You won't find /healthz in the file. Ignite logged "routes":4: the two functions above, plus the built-in health and readiness routes.

The request id changes every call. The rest is the shape. code is json.validation and errors[0].pointer is /qty. The rule is the annotation on qty. If a quantity of zero is a real order, [[= json::min(1)]] is the line you change. If it isn't, the client is wrong and you leave the server alone.

The same run then called GET /orders/1 with no Authorization header.

auth.missing means the caller didn't send a bearer token. You don't edit the handler for that. If the code had been auth.forbidden, the line to read is auth::require("orders"), next to the token's roles claim. The route in the log is the template /orders/{id}, not /orders/1, so one bad id doesn't mint a new series.

It still gets things wrong

The compile step and the types catch a missing parameter name, a capture that doesn't match, and a return type that isn't a response. They won't catch a minimum of 1 that should have been 0, or an issuer you pasted from an example. Read the diff.
