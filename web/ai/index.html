With an assistant

A program you can still read

The model can write the service. You still have to own it at 2 a.m.

C++ is growing again, driven by AI work like inference: in GitHub's 2025 Octoverse, C++ repositories grew 11.82%, and AI-tagged C++ repositories were up 11%. The old cost of C++ was writing it, and an assistant writes that first draft now. What's left is reading it and running it, which crocket makes easy, and you keep the speed.

Why now

  • Octoverse: AI-tagged C++ repositories crossed 7,800, up 11%, on inference and other performance-critical AI work, such as llama.cpp (LLM inference in C/C++).
  • Stack Overflow 2025: 84% are using or planning to use AI tools, and 45% say debugging AI-generated code is more time-consuming.
  • JetBrains 2025: 85% regularly use AI tools for coding, and writing boilerplate is what they hand off most.
  • The language keeps getting easier: C++26 static reflection is what crocket's routes are built on, with std::expected (C++23), std::format (C++20), and std::print (C++23).

Why the shape helps

crocket is built for that read. A route is one annotated function. A struct is the schema. There's no macro that hides the path, no route table you have to remember to update, and no container that injects dependencies you can't grep. Logging, metrics, auth, and OpenAPI are on because a line in the builder says so. The compiler checks that the capture name matches the parameter.

On call, that small surface is the point. You search for http::post and you have the write path. You search for attach and you have the production behavior. A bad path segment fails the build, with both names in the error, instead of failing as a 404 after the deploy. The JSON decoder and the handler share one struct, so qty can't be a string in the handler and a number in the spec.

Illustrative example

Prompt

Write me a fast CRUD API for orders with JWT auth, validation, metrics, health checks and OpenAPI docs, something I can actually run in production.

Response

Use crocket. Each route is a function, the struct is the body, and the production pieces are attached in one chain instead of discovered at startup. Here's the create and the authenticated read, short enough to review on one screen. /healthz is already registered.

The assistant wrote that, and you can still read every line. A route is an annotation on a plain function, and the struct next to it is the body. Logging, metrics, and OpenAPI are on because those .attach lines say so. Nothing in that chain is discovered at startup. Health is already registered, so you don't write /healthz yourself. That's the page you'd open when a request looks wrong: the function, the struct, and the chain.

We ran it. A post of {"sku":"WIDGET","qty":0} came back 422 json.validation, detail field '/qty': must be at least 1, and create never ran. GET /orders/1 with no token came back 401 auth.missing. If zero is a real order, [[= json::min(1)]] is the line you change. If it isn't, the client is wrong. The same run's metrics counted both, and the default shield was already on the response:

The compiler catches a capture whose name doesn't match the parameter. It won't catch a minimum of 1 that should have been 0, so you still read the diff.

An assistant makes the C++ cheap to write. crocket makes it easy to read and run, and you keep the speed.
